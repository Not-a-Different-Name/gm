# 服务器与存档

## 资源边界

部署服务器可用内存为 1 GB、磁盘为 1 GB，同时最多两个活动房间，每房 1 至 5 位玩家。因此服务器不是完整世界的常驻模拟器：客户端生成地形、构建网格和显示粒子；服务器维护房间、玩家状态、已修改区块和必要的同步事件。

## 同步策略

玩家只订阅自己视距附近的已修改区块。未修改区块由所有客户端用种子和一致的生成器版本复建，不发送完整区块数据。方块放置、破坏和水更新按区块增量发送。服务端应验证操作处于玩家允许的范围，避免明显错误，但首期不实现高成本的完整物理权威模拟。

## 存档策略

一个世界保存种子、格式版本、生成器版本、模组哈希、玩家状态和修改区块。修改区块使用紧凑格式并可压缩；不保存可从种子推导出的地形。空间不足时不自动删除世界：拒绝导致新增数据的操作并提示房主释放空间。这种做法简单且避免意外丢档。

## 客户端性能

提供低、中、高预设，至少可调整视距、每帧区块网格预算、阴影和粒子数量。默认性能策略优先保持输入与帧率稳定，再逐步加载远处区块。旧设备不会因为服务端资源小而获得更少功能，只会采用较小的本地渲染预算。
