# 开发规范

## 工具链

- 使用 `pnpm` 管理依赖和工作区，不提交 `node_modules`。
- 使用 TypeScript 严格模式；禁止隐式 `any`。
- 使用 ESLint 发现类型和异步错误，使用 Prettier 统一格式。
- 使用 Vitest 测试纯逻辑；浏览器流程稳定后加入 Playwright 冒烟测试。

在提交前运行：

```bash
pnpm format:check && pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

## 命名和文件

- 文件和目录使用 `kebab-case`，例如 `chunk-coordinate.ts`。
- 类、接口、类型、枚举使用 `PascalCase`。
- 函数和变量使用 `camelCase`；真正的常量使用 `UPPER_SNAKE_CASE`。
- 一个文件解决一个清楚的概念。超过约 300 行时，先评估是否应按职责拆分。
- 导出的类型应与实现分开导入，使用 `import type`。

## 代码原则

世界规则必须保持确定性，不读取当前时间、随机全局状态或浏览器环境。随机行为统一由世界种子派生的随机源产生。

方块、材质、实体和生成器使用命名空间 ID，例如 `gm:grass` 或 `example:marble`。禁止把同一个字符串或数值散落在多个文件中。面向模组公开的 API 应兼容演进：添加可选字段优先于修改或删除现有字段。

注释和文档以中文为主。对外 API、非直观算法和性能取舍应说明“为什么”；不要使用重复代码含义的注释。

## 测试策略

优先覆盖不依赖 GPU 或网络的逻辑：区块坐标换算、种子随机序列、区块序列化、方块注册冲突、液体更新和存档迁移。每个缺陷修复应先添加能复现问题的测试，再修复实现。

## 资源与许可证

后续加入纹理、音效和第三方代码时，必须在 `NOTICE.md` 或 `assets/licenses/` 记录来源、许可证和版本。只允许可商用、可再分发且满足项目发布方式的资源。
