# 本地世界存档

## 存储位置

单机世界使用浏览器的 IndexedDB，数据库名为 `gm-worlds`，存储表为 `worlds`。种子决定基础地形；每个存档槽使用独立 ID，因此相同种子可建立多个命名存档，不同种子也互不影响。

## 保存内容与格式

存档保存名称、世界元数据（种子、游戏版本、生成器版本、模组清单、格式版本 `formatVersion`）、玩家坐标（可选物品栏持有数量）和被玩家改动的区块方块差异。基础地形、海水和树木不写入 IndexedDB，因为它们能够由种子和生成器版本重新生成。每次方块放置或破坏后约 600 毫秒写入一次，连续操作会合并为一次保存；暂停菜单提供立即保存按钮，返回主界面前会强制落盘防抖定时器内的最后编辑。

导出文件就是存档记录的 JSON 原文（带缩进，便于人工检查与修复）。`packages/storage/src/world-format.ts` 统一序列化（`serializeWorld`）、解析（`parseWorldFile`）与迁移（`migrateWorldData`）：解析和读档时逐字段校验结构，错误按 `invalid-json` / `corrupted` / `too-new` 归类；`formatVersion` 高于当前版本（`@gm/core` 的 `WORLD_FORMAT_VERSION`）时拒绝读取并提示升级，低于当前版本时按模块级 `MIGRATIONS` 迁移链逐级升级（当前 v1 链为空，未来格式变更在此追加）。保存失败按 `classifySaveError` 区分浏览器配额耗尽与其他错误，分别给出提示。

## 恢复过程

打开世界时，游戏先用种子生成区块，然后把保存的差异覆盖到对应区块，最后恢复玩家位置。差异区块使用本地索引和方块 ID 表示，体积远小于完整区块，适合无限地图的长期保存。蔓延水不存档，读档后由存档中的水源重新蔓延。

主界面"进入世界"会等待恢复完成（按钮短暂显示"正在恢复…"）；读档失败不会进入空白世界——版本过新提示升级，数据损坏弹窗提供"删除该存档并进入新世界"。

## 存档管理界面

主界面的"管理存档"进入独立界面（泥土贴图蒙版；主界面为石头蒙版）。列表按种子过滤、按最后保存时间倒序，每行只有"进入"和"管理"两个按钮，行内显示摘要（修改区块数、玩家坐标、保存时间）。"管理"展开详情面板：进入世界、重命名、导出、删除、返回列表。重命名/删除当前存档会即时同步主界面显示；删除当前存档后再次进入将创建新世界。导入存档会校验 JSON 格式与结构：损坏或版本过高按类提示，同 id 已存在时确认覆盖，种子与当前不同时自动同步主界面的种子输入。

## 当前限制

尚未提供跨浏览器同步；清除浏览器站点数据会删除本地存档。服务器持久化会在联机阶段使用兼容的"世界元数据 + 区块差异"模型，但不会直接访问浏览器 IndexedDB。
