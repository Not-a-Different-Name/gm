# 项目架构

## 目标

GM 是接近经典方块沙盒风格的网页游戏。本体提供确定性世界、方块交互、角色移动、渲染和联机基础；模组可以在不修改本体内部实现的前提下注册方块、材质、生成规则、配方、实体、UI 与玩法逻辑。

核心原则是：同一世界版本、种子、模组集合和玩家操作，必须导出同一世界状态。这样单机存档、联机同步与问题复现才可靠。

## 包的职责

| 路径                  | 职责                                       | 可以依赖                |
| --------------------- | ------------------------------------------ | ----------------------- |
| `apps/web`            | 浏览器入口、页面、输入、游戏启动           | 所有公开包              |
| `packages/core`       | 坐标、区块、世界规则、方块注册、生成与事件 | 不依赖浏览器或 Three.js |
| `packages/renderer`   | Three.js 网格、材质、相机、粒子            | `core`、Three.js        |
| `packages/storage`    | IndexedDB 与服务端存档格式、版本迁移       | `core`                  |
| `packages/mod-api`    | 供模组使用的稳定 API 和类型                | `core` 的公开类型       |
| `packages/mod-loader` | 本地模组发现、校验、加载与生命周期         | `mod-api`               |
| `apps/server`         | WebSocket 房间、持久化、模组哈希校验       | `core`、`storage`       |
| `mods`                | 示例模组和本地开发模组                     | `mod-api`               |

后续目录在对应阶段创建。不要为了方便而让 `core` 引用 Three.js、DOM、IndexedDB 或 WebSocket；这些依赖会使测试、服务器运行和未来渲染替换变得困难。

## 世界数据流

```text
世界种子 + 游戏版本 + 模组清单
            │
            ▼
      确定性区块生成 ──► core 世界状态 ──► renderer 网格与粒子
            │                    │
            │                    ├──► storage 增量存档
            │                    └──► server 区块增量同步
            ▼
    仅保存被修改区块
```

区块基础尺寸为 `16 × 16 × 256` 方块。无限世界按玩家附近视距产生并卸载区块；固定世界复用同一生成器，只增加可配置的区块边界。未修改区块不写入存档，重新进入时由种子生成；修改过的区块以覆盖数据恢复。

## 依赖方向

依赖只能从应用层指向基础层，不能反向依赖。模组绝不能导入 `core` 内部文件，而只能使用 `mod-api` 导出的稳定接口。模块之间通过显式类型、命令和事件通信，不共享可任意写入的全局对象。

## 版本兼容

世界元数据至少记录：格式版本、游戏版本、世界种子、生成器版本和模组清单哈希。读取旧存档时，先执行明确的迁移步骤；无法安全迁移时必须报错而不是静默损坏世界。
