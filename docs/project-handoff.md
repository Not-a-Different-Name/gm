# 项目交接与完整计划

本文档用于在中断或重新打开项目后快速恢复开发。它记录当前实现、已确认需求、约束、运行方式和后续任务顺序。

## 当前状态

项目是一个桌面浏览器体素沙盒游戏，采用 TypeScript、Vite、Three.js 与 pnpm 工作区。当前已有一个可操作的单机原型：

- 确定性种子地形：草地、泥土、石头、沙子、基岩、静态水与跨区块树木。
- 无限与固定边界世界接口；视距半径 2（5×5 区块，fixed 模式被边界裁剪为 3×3）的分帧流送加载与远处网格释放。
- 第一/第三人称、鼠标视角、WASD、基础碰撞、跳跃与飞行。
- 左键长按破坏（含进度覆盖盒、程序化破坏音效与掉落物）、右键放置（消耗物品栏 1 个）、底部热键栏（数字键/滚轮/点击切换，显示持有数量）、破坏掉落物走近自动拾取、方块颜色粒子对象池。
- 主界面、Esc 暂停、继续、返回主界面及画布右键/拖拽手势拦截。
- IndexedDB 本地存档：同一种子支持多个命名存档，保存玩家位置、物品栏持有数量与已修改区块差异；独立存档管理界面支持重命名、删除、导出/导入 JSON、格式版本迁移与损坏提示、保存失败/配额提示；进入世界前等待存档恢复完成。
- 原创代码生成的 16×16 像素图集；草方块、木头等支持顶面/侧面/底面纹理标识，树叶有 alpha 裁切孔洞。
- 性能优化：实心地形贪心网格（合并共面，着色器注入图集平铺）、区块分帧流送（每帧数据 2 / 网格 1 / 待办重建 1，距离最近优先）、区块缓存上限 256 块按四条件逐帧淘汰（含水区块不淘汰）、视距半径 2。

当前远程主分支包含存档完善阶段的全部提交（最新功能提交 `e3fe806`）。本地参考截图不会提交到仓库，已被 `.gitignore` 忽略。

## 已确认需求

- 技术栈：TypeScript + Vite + Three.js；pnpm 工作区；严格 TypeScript、ESLint、Prettier、Vitest。
- 目标平台：桌面浏览器，不要求触控兼容。
- 世界：种子生成、接近经典方块沙盒的区块处理；同时支持无限和固定尺寸地图；景观偏大；不生成矿物。
- 方块：先实现破坏、放置、选择栏与方块色粒子；水必须出现在生成地图中；暂不做合成和熔炉。
- 移动：正常移动、跳跃、飞行，第一/第三人称；不做伤害。
- 模组：本地受信任 JavaScript/TypeScript 模组优先；未来支持 JSON 数据；可扩展方块、材质、生成、配方、实体、UI 和行为。
- 联机：未来支持两个活动房间、每房 1–5 人；房间开始前校验模组 ID、版本和哈希。
- 存储：服务器磁盘预算 1 GB、内存可用约 1 GB；磁盘满时拒绝新增数据并提示，不自动删除世界。

## 运行与检查

本机可能未将 `pnpm` 加入 PATH，因此统一使用 Corepack：

```bash
corepack pnpm install
corepack pnpm dev
```

完整质量门禁：

```bash
corepack pnpm format:check
corepack pnpm lint
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
```

开发时请打开可见浏览器窗口验证网页交互，而不仅使用后台截图。开发服务默认地址为 `http://127.0.0.1:5173`。

## 目录与边界

| 路径                  | 职责                                                       |
| --------------------- | ---------------------------------------------------------- |
| `apps/web`            | 网页入口、菜单、输入、HUD、IndexedDB 调用                  |
| `packages/core`       | 方块、区块、坐标、种子地形、水流规则、世界边界、世界元数据 |
| `packages/renderer`   | Three.js 网格、图集、相机、玩家、粒子、区块流送            |
| `packages/storage`    | IndexedDB 世界存档、存档格式校验/迁移与数据类型            |
| `packages/mod-api`    | 后续创建：稳定模组公开 API                                 |
| `packages/mod-loader` | 后续创建：本地模组发现、哈希与加载                         |
| `apps/server`         | 后续创建：WebSocket 房间和服务器持久化                     |

`core` 绝不能依赖 DOM、Three.js、IndexedDB 或网络。模组只能依赖未来的 `mod-api`，不能导入内部实现。

2. 支持图集从资源包或模组替换，避免把图片路径硬编码在网格中。
3. 加入低/中/高画质预设：视距、像素比、粒子数量与每帧网格预算（每帧网格预算已可通过 `VoxelWorldViewOptions` 配置，预设档仍待做）。
4. 优先处理生产包约 505 kB 的 Vite 警告，例如按 Three.js/游戏模块拆包。

### 6. 联机与服务器

1. 创建轻量 Node.js WebSocket 服务，仅维护两个活动房间。
2. 服务端保存房间、玩家状态与已修改区块增量；不要在服务器常驻完整种子地形或渲染数据。
3. 同步视距附近区块差异和玩家位置；初期只做合理操作范围校验。
4. 按房间非活动状态写盘并释放内存；磁盘满时拒绝写入而不自动删除。

## 已知限制与注意事项

- **参考图与版权**：参考图只用于观察色调、天空、水面、方块密度和树叶轮廓。不要复制原版纹理、UI 或音效；使用原创或许可兼容资源，并记录来源与许可证。
- **图像生成**：当前会话没有内置图像生成工具。若未来要生成新的位图资产，可使用可用的图像生成工作流；必须将最终项目资产放入工作区并保留许可证信息。
- **右键手势**：网页已在捕获阶段阻止画布右键菜单、辅助点击、拖拽与指针移动默认行为。如果仍出现轨迹，通常来自浏览器扩展或鼠标手势软件，它们会先于网页事件处理，需由用户在对应工具中关闭。
- **树叶**：已使用透明像素和 `alphaTest` 形成视觉孔洞，但区块网格仍会为相邻树叶生成面；性能优化时可改用专门的叶片网格或合并规则。
- **水与天空**：昼夜天空、水面波纹/流动、水下视角、游泳与像素云层均已实现。水是低级方块、可被填充，且在拾取上与空气同属性：射线穿透水命中水后的实体方块，放置目标为该方块朝向玩家一侧的邻格，邻格为水格时实体方块直接替换水格；左键同样穿透水（不直接命中水格，移除水用方块填充或挖开容器）。地形生成的海洋/湖泊仍为静态水源，仅被玩家挖开或接水后才流动。
- **物品栏与掉落物**：物品栏初始为空（先收集后建造），旧存档无物品栏字段时读档得到空物品栏；掉落物只存在于运行时（不存档），掉进水里会穿透水沉到水底；破坏/放置音效为 Web Audio 程序化合成，浏览器自动播放策略下首次点击后才出声。
- **存档**：当前用浏览器 IndexedDB 保存；清除站点数据会清除本地存档。存档可重命名/删除/导出导入（见 [本地存档](local-saves.md)），尚未支持跨浏览器同步。
- **浏览器测试**：可见浏览器测试窗口要保留给用户确认；启动 Vite 服务时使用隐藏终端，不强制关闭用户窗口。
- **Git**：推送偶尔因 GitHub 网络断开失败。不要丢弃本地提交；网络恢复后执行 `git push origin main` 重试。
- **代码风格**：保持中文文档和注释为主；不使用隐式 `any`；公开 API 明确类型；文件名 `kebab-case`；避免跨层依赖。
