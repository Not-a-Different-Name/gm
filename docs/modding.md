# 模组设计

## 模组目标

模组用于扩展或改写玩法，而不要求修改游戏本体。用户环境被视为受信任，因此本地模组可以执行 JavaScript；但仍应通过公开 API 注册内容，避免依赖本体私有实现。

## 加载方式

开发模式优先从本地 `mods/` 目录加载。浏览器无法在用户不授权的情况下扫描任意目录：发布版本将通过文件夹选择或模组包导入获取用户明确授权的文件。每个模组提供清单，至少包含 ID、版本、入口、依赖和内容哈希。

## 联机规则

开房时服务器收集房间模组清单及哈希。客户端加入前进行比较：缺少模组或哈希不同，则提示用户同步；全部一致后才能加入。这个机制避免不同方块定义或生成规则破坏同一个世界。

## 未来 API 范围

首批公开能力将包括：注册方块和材质、注册生成器钩子、响应方块交互、注册物品及配方、注册实体和 UI。合成与熔炉不在本体首版实现，但其注册接口会在对应阶段由模组 API 提供。

## 稳定性约定

模组只能使用版本化的 `@gm/mod-api`。游戏升级时，破坏性变更需提升 API 主版本；模组清单声明兼容范围。模组数据写入世界时必须使用自身命名空间，避免与本体或其他模组冲突。
